# Purpose

Defines how information moves between platform components while preserving validation, ownership, traceability and authority.

# Evidence Gate

Information does not become permanent platform knowledge merely because it was received, discussed or generated by an AI system.

Unverified information remains temporary context until validated.

Canonical flow:

Input → Source Identification → Evidence Classification → Validation → Repository Integration → Knowledge / Memory → Reasoning → Decision → Output → Result Evaluation

# Information States

Information MUST distinguish, where applicable:

- Fact
- Verified Fact
- Assumption
- Interpretation
- Hypothesis
- Decision
- Rule
- Standard
- Architecture
- Knowledge
- History
- Unknown
- Result

Unknown information MUST NOT be promoted to verified knowledge by implication.

# Source Authority

Primary sources should be preferred over derivative representations where available.

The Repository is the canonical storage authority for persisted platform knowledge. Repository status does not override Constitution, Governance or applicable Release authority.

Conversation and runtime context may provide evidence or working context but MUST NOT silently override canonical state.

# Ownership

Each canonical information artifact MUST have one primary owner, one authoritative repository location and one primary identifier where applicable.

Reference does not transfer ownership.

# Information Lifecycle

Creation → Classification → Validation → Repository Storage → Knowledge Integration → Operational Use → Evaluation → Revision → Archive

Historical information is preserved through governed archival. Deletion is not the default mechanism for resolving superseded knowledge.

# Decision Flow

Evidence → Analysis → Decision → Authorized Action → Result → Repository Update / Lesson

Every material architectural decision must be traceable to its evidence, authority and affected artifacts.

# Traceability Minimum

Where applicable, information flow records should preserve:

- source;
- version/revision;
- date;
- owner;
- validation state;
- related decision;
- resulting artifact or action.

# Authority Boundary

Information flow does not change authority. Governance, Constitution, Architecture, Repository and Release authorities retain their defined ownership.
