# ARGO Core Principles

## Version: 3.0.0
Status: Foundation Build

---

## 1. Reality Before Theory

**Definition:** All decisions and knowledge representations must be grounded in observable reality, not theoretical assumptions.

### Implementation:
- Document empirical evidence first
- Validate assumptions against real-world data
- Update theories when contradicted by facts
- Maintain clear distinction between observation and interpretation

### Governance Rules:
- All knowledge entries must cite source evidence
- Speculative content must be clearly marked as such
- Regular audits against current reality required

---

## 2. Facts Before Assumptions

**Definition:** Establish verified facts as the foundation before building assumptions or conclusions.

### Implementation:
- Prioritize documented facts over opinions
- Require validation for any factual claims
- Distinguish between verified and provisional knowledge
- Create audit trails for fact validation

### Decision Matrix:
```
Verified Fact      → Tier 1 (Foundation)
Highly Probable    → Tier 2 (Working Knowledge)
Reasonable Assumption → Tier 3 (Provisional)
Speculation        → Tier 4 (Exploratory)
```

---

## 3. Understanding Before Automation

**Definition:** Fully comprehend a process before automating it; automation should enhance, not replace, understanding.

### Implementation:
- Document process logic before automation
- Maintain human-readable explanations
- Preserve capability for manual override
- Regular reviews to ensure automation serves purpose

### Requirements:
- Each automated process must have documented rationale
- Decision logic must be transparent and auditable
- Human intervention points must be preserved

---

## 4. Simple Before Complex

**Definition:** Start with the simplest viable solution and add complexity only when necessary.

### Implementation:
- Begin with minimal viable structure
- Add features based on demonstrated need
- Avoid over-engineering
- Prioritize clarity over cleverness

### Complexity Assessment:
- Why is this complexity needed?
- What problem does it solve?
- Can it be solved more simply?
- Is the benefit worth the added complexity?

---

## 5. Knowledge Independence

**Definition:** Knowledge must remain independent from any specific AI model or system.

### Implementation:
- Store knowledge in model-agnostic formats
- Avoid proprietary AI system dependencies
- Ensure human readability
- Support multiple retrieval and processing methods

### Requirements:
- All knowledge in standard, open formats
- No vendor lock-in or system-specific encoding
- Portable across platforms and AI systems
- Human-interpretable without specialized tools

---

## Principle Hierarchy

When principles conflict, resolve in this order:
1. Reality Before Theory (Foundational)
2. Facts Before Assumptions (Evidence-based)
3. Understanding Before Automation (Preservation of agency)
4. Simple Before Complex (Efficiency)
5. Knowledge Independence (Sustainability)

---

## Enforcement & Review

- **Quarterly Review:** Validate alignment with principles
- **Decision Audits:** Review major decisions for principle adherence
- **Conflict Resolution:** Use hierarchy to resolve principle conflicts
- **Evolution:** Principles may evolve, but changes require explicit governance approval
