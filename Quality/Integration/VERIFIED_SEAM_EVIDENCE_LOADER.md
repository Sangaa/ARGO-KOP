# Verified Seam Evidence Loader

The loader is the bridge from the repository itself into the Verified Seam Evidence Registry.

It accepts a candidate only when all three referenced local artifacts are valid and the upstream evidence boundary has established explicit verification:

```text
Contract + Test + Materialized Execution Trace
        ↓
Evidence Verification
        ↓
Registry Promotion Gate
        ↓
CONNECTED
```

## Required Artifact Rules

### Contract

- repository-relative path;
- regular file;
- present inside the bounded evidence root.

### Test

- repository-relative path;
- regular file;
- present inside the bounded evidence root.

### Trace

The trace reference must be:

- repository-relative;
- a regular file;
- JSON;
- a JSON object;
- `record_type == EXECUTION_TRACE`;
- populated with non-empty `trace_id`, `task_id`, `session_id`, and `final_status`.

Missing or malformed artifacts are not synthesized. The loader excludes the incomplete candidate.

## Verification Boundary

Artifact validity is necessary but is not sufficient for semantic certification.

A candidate must also carry explicit `verification_status == VERIFIED` from the upstream evidence verifier before the registry can promote it to `CONNECTED`.

The loader does not infer verification from filenames, keywords, file existence, or shape alone.

## Runtime Evidence Boundary

A valid materialized trace proves only that the referenced artifact satisfies the minimum execution-trace schema. It does not, by itself, prove that the trace was generated by the exact runtime seam under review.

For canonical seam certification, the upstream verification path must establish the relationship between the actual runtime-produced trace and the matching outcome/evidence lineage.

Temporary test-target traces are valid for bounded integration testing but must not be treated as permanent canonical repository evidence.

## Registry Boundary

The loader is an evidence-validation component, not a discovery mechanism and not a semantic authority. The Verified Seam Evidence Registry remains a promotion gate and requires:

- canonical seam key;
- unique seam record;
- repository-relative evidence references;
- explicit `verification_status == VERIFIED`.

A loader-level `CONNECTED` result is therefore scoped to the submitted evidence set and does not constitute a repository-wide integrity claim.
