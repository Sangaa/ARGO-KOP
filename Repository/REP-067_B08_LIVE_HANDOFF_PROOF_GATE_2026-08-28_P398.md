## MINIMUM PROOF CONTRACT
A future observation may be considered B08 live-handoff evidence only if all conditions below are simultaneously observed on the same exact execution context:

1. **Caller identity:** the actual connected RUN-010 caller is identified by executable code path, not by a test-only direct invocation.
2. **Authorization provenance:** the caller enters the governed boundary with explicit authorization and fails closed when authorization is absent.
3. **Identity propagation:** execution_id, task_id, session_id, and source_trace_id remain identical across RUN-010 -> ENG-006 -> SRV-009.
4. **Boundary attribution:** an observable event proves the RUN-010 caller crossed into the governed ENG-006/SRV-009 adapter.
5. **Side-effect control:** observation uses a non-production connector or equivalent controlled sink; no real provider/production side effect is permitted.
6. **Persistence/read-back:** if a write is part of the observation, the governed write result includes explicit post-read verification.
7. **Exact-head attribution:** CI evidence is tied to the exact tested commit SHA; merge-ref or merge-commit execution is not substituted for head evidence.
8. **Negative control:** an unauthorized or disconnected path must fail without repository/provider mutation.
9. **No promotion by implication:** passing this gate proves only the observed handoff seam; it does not authorize production promotion until REL-009 reconciliation is separately completed.
