## RE-ENTRY
Resumed from P373. The objective was to reduce the unresolved REL-009 gates B07 and B08 to the smallest justified observation boundary before any implementation.

## CURRENT-MAIN INSPECTION
The canonical REL-009 matrix requires independent callable-consumer evidence and runtime execution evidence for `RUN-010 → SRV-009`. The current `connected_spine_runner.py` builds a simulated plan and calls `execute(... final_status="SIMULATED", side_effect=False, ...)`; it records decision/execution traces but does not dispatch to `SRV-009`.

Therefore the existing connected spine can provide trace evidence, but it cannot by itself satisfy B07/B08.

## MINIMUM OBSERVATION DESIGN
B07 requires a callable consumer whose execution context is demonstrably RUN-010 and whose target is SRV-009. The evidence must identify the callable boundary and preserve authorization/provenance context.

B08 requires an execution trace showing that the same RUN-010 execution context actually reached the SRV-009 dispatch boundary. A trace producer alone is insufficient; the observed event must correspond to the service dispatch/call boundary.

The minimum implementation should therefore introduce only a testable, isolated consumer seam capable of recording an explicit dispatch event. It must not turn the normal connected-spine simulation path into production side effects, and it must not weaken existing authorization or safety gates.

## REUSE BOUNDARY
PR #63 may be used as historical design evidence for the consumer seam, but its broad divergent branch must not be copied wholesale. Only concepts that reconcile cleanly with current-main contracts may be reused.

## EVIDENCE CONTRACT
The future isolated test must establish, at minimum:

1. `RUN-010` is the originating execution context.
2. `SRV-009` is the explicit target.
3. The callable consumer boundary is observed, not inferred from prose.
4. The runtime dispatch event is recorded and attributable to the same execution.
5. Authorization/provenance metadata remains intact.
6. The observation is side-effect controlled for testing.
7. Exact HEAD and governed CI execution are recorded.

## DECISION
The minimum safe mutation boundary is now defined conceptually, but no specific current-main file change is committed in P374. This avoids premature implementation before reconciling the historical consumer seam with the current runtime contracts.

No Canonical relationship promotion is permitted from this design alone.
