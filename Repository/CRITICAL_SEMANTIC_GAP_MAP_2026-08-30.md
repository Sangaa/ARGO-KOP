# E. Reusable learning

### Learning 1

`CANONICAL IDENTITY != PROMOTED OPERATIONAL AUTHORITY`

A canonical path/identity can still be Proposed, Integrity Hold or Revalidation Required. Canonicality answers "which artifact owns this logical identity?"; status/authority answers "what may this artifact currently authorize or prove?"

### Learning 2

`CROSS-LAYER HOLD MAY CONTAIN MULTIPLE INDEPENDENT SUBGATES`

A domain-wide HOLD should be decomposed into semantic compatibility, implementation, runtime reachability, consumer coverage, authentication and global-certification subgates. Closing one must not erase the others.

### Learning 3

`STATUS DRIFT MUST NOT REOPEN CLOSED REALITY`

When a root/queue summary lags behind newer direct domain evidence, classify the summary as stale and synchronize it later; do not rerun completed identity work merely because an older status line remains.

### Learning 4

`TEXT CAN CLOSE CONTRACT SEMANTICS; TEXT CANNOT EARN EXECUTION OR AUTHENTICITY`

Substantive document review can prove compatibility/no-direct-contradiction within the inspected contract set. It cannot establish runtime reachability, provider execution, independent authenticity or observed cognitive benefit.
