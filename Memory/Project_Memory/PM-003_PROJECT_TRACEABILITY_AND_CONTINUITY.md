# PM-003 — PROJECT TRACEABILITY AND CONTINUITY

Version: 1.0.0
Status: Build-01 / Integrity Hold

## Purpose

Ensure a project can be resumed across sessions without reconstructing its meaning from conversation alone.

## Continuity Chain

```text
Project Context
      ↓
Current State
      ↓
Decisions / Constraints
      ↓
Evidence / Dependencies
      ↓
Actions / Outcomes
      ↓
Lessons
      ↓
Next Recoverable State
```

## Minimum Continuity Set

A recoverable project context should expose:

- where the project is now;
- what has already been decided;
- what evidence supports the current state;
- what remains unresolved;
- what should happen next;
- which artifacts are authoritative;
- which information is historical or provisional.

## Relationship Integrity

Project links should identify relationship type and status where practical. Broken or unresolved references must remain visible rather than silently repaired by inference.

## Session Boundary

At session closure, material project changes should be linked to the Engineering Journal and relevant Decision Memory records. At session start, Project Memory should be sufficient to recover project-local context.

## Boundary

This artifact defines continuity and traceability expectations. It does not replace the repository master index or decision authority.
