# ARGO KOP — Operational Memory

Domain: Memory
Subdomain: Operational_Memory
Status: Build-01 / Integrity Hold
Purpose: Preserve operationally relevant observations, active context, outcomes, and reusable experience without replacing canonical Constitution, Governance, Architecture, or Repository authority.

---

## Scope

Operational Memory records what happened during active work and what remains useful for subsequent execution.

It may contain:

- observations;
- operational context;
- execution outcomes;
- validated lessons;
- unresolved operational questions;
- links to decisions, evidence, projects, and engineering journal entries.

It must not silently become canonical policy.

## Authority Boundary

Operational Memory is subordinate to:

1. Constitution;
2. Governance;
3. Architecture;
4. Repository authority;
5. applicable project and decision authority.

Memory can preserve experience and evidence. It cannot promote an observation into a rule without the applicable governance path.

```text
  ↓

Validated / Rejected / Deferred

```

## Integrity Rule

Operational Memory must preserve provenance. A memory item without sufficient source, context, or status must remain explicitly uncertain.
