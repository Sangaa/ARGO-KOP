# OPM-001 — OPERATIONAL MEMORY MODEL

Document ID: OPM-001
Version: 1.0.0
Status: Build-01 / Integrity Hold
Category: Memory / Operational Memory
Canonical: Candidate — pending domain consolidation

---

## Purpose

Define the minimum structure of an operational memory item so that active experience can be retained, traced, evaluated, and reused without being confused with canonical policy.

## Memory Item

An operational memory item should preserve, where applicable:

- `Memory ID`
- `Observed At`
- `Context`
- `Source / Evidence`
- `Observation`
- `Action`
- `Outcome`
- `Classification`
- `Confidence`
- `Related Decision`
- `Related Project`
- `Related Engineering Journal`
- `Lessons / Experience`
- `Validation State`
- `Reuse Conditions`
- `Supersedes / Superseded By`

## Classification

Use explicit classes rather than silently treating every memory item as truth:

- Observation
- Fact candidate
- Assumption
- Hypothesis
- Outcome
- Lesson
- Experience
- Rejected inference
- Open question

## Authority Boundary

A memory item is not a governance rule merely because it is repeated or successful. Promotion to a rule requires the applicable authority path.

## Relationship Principle

Operational Memory should link outward to evidence, decisions, projects, and engineering records rather than duplicating their authority.

## Integrity Rule

When provenance is insufficient, preserve the item with an explicit uncertainty state instead of inventing missing context.
