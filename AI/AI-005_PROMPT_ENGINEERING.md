# Purpose

This document defines the Prompt Engineering standards used throughout ARGO KOP.

Prompt Engineering ensures deterministic, repeatable and repository-driven AI behavior.

Prompts are engineering interfaces.

They are not sources of truth.

---

# Objectives

Prompt Engineering shall:

Produce deterministic results.

Reduce ambiguity.

Support repository synchronization.

Improve engineering consistency.

Minimize unnecessary conversation.

Maximize engineering productivity.

---

# Prompt Engineering Philosophy

The repository defines reality.

Prompts define execution.

A prompt shall never replace repository evidence.

# Prompt Structure

Every engineering prompt shall contain:

Repository Context

# Engineering Prompt Rules

Every engineering prompt shall:

Reference the latest repository.

Use the latest repository baseline.

Modify complete canonical documents only.

Never request partial replacements.

Never request repository assumptions.

Never bypass architecture.

Never bypass governance.

# Repository Awareness

Before execution the AI shall know:

Current Repository Baseline

Current Folder

Repository Priority

---

# Prompt Optimization

Engineering prompts shall:

Be short.

Be deterministic.

Avoid unnecessary explanations.

Avoid repeated summaries.

Focus on engineering output.

Repository output always has priority over conversational output.

---

# Conversation Optimization

Reduce conversation whenever possible.

Continue engineering automatically.

Only stop when:

Repository ambiguity exists.

Architecture conflict exists.

Governance conflict exists.

Missing repository dependency exists.

Otherwise continue.

---
