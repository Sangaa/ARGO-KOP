## Critical epistemic correction

The repository contains substantial evidence that ARGO's learning methodology is deliberately designed to support discovery, correction, validation, transfer, reusable learning, and generative knowledge. However, the existence of a method, protocol, engine, fixture, or promotion gate is **not by itself evidence that a particular ARGO instance independently invented or improved that method**.

This distinction is now elevated to a HORUS finding because it materially changes how the historical evidence should be interpreted.

## Decisions

### DEC-H040 — Architecture of learning is not proof of autonomous discovery
A documented capability or learning architecture establishes that the system is designed or permitted to perform an operation. It does not establish that the operation was independently discovered by ARGO.

### DEC-H041 — Guided-learning evidence must be attributed to its guidance level
MEM-008 explicitly defines guidance levels G0–G4 and describes a training process involving taught rules, hidden tests, guided discussion, error recognition, rule revision, and re-testing. Therefore historical cases using this method must retain their guidance level before being considered evidence of independent discovery.

### DEC-H042 — Repository-authored method and ARGO-generated method are different provenance classes
A rule written by a human, governance process, or repository artifact is inherited knowledge for attribution purposes even if ARGO later applies it successfully. A generated hypothesis becomes evidence of independent generation only when its origin is separately demonstrated.

### DEC-H043 — Operational learning is stronger evidence than static architecture, but still not automatically autonomous
A sequence of observed tool use, failure, correction, new reusable rule, and later reuse is behavioral evidence of learning. Attribution still requires checking whether the correction was supplied, strongly guided, retrieved, or independently selected.

### DEC-H044 — Cross-domain recurrence must be traced to the source method
The repository contains explicit cross-domain learning goals and connector training that deliberately generalize observations into reusable rules. Recurrence across domains therefore supports learning/transfer behavior, but cannot alone prove that ARGO discovered the abstraction without guidance.

### DEC-H045 — Promotion architecture is evidence of epistemic discipline, not intelligence level
ENG-015 and the associated learning records explicitly separate experience, learning candidate, validated learning, and promoted knowledge. This supports a strong claim about the system's governance design; it does not raise the autonomy score by itself.

### DEC-H046 — Historical evidence must distinguish designed learning from discovered learning
HORUS must maintain two separate evidence tracks:

`Learning-system capability evidence`
versus
`Instance-level autonomous-learning evidence`.

The first can be strong while the second remains unresolved.

## New findings

### F-H008-01 — The repository contains a mature learning methodology
MEM-008 specifies a repeatable cycle of teaching, hidden testing, observation, safe error, guided discussion, self-diagnosis, rule revision, re-application, experience recording, and changed-context testing. This is strong evidence that ARGO was intentionally equipped with a method for producing reusable reasoning rather than mere rule memorization.

### F-H008-02 — The method explicitly measures independence
MEM-008 distinguishes direct instruction, hints, prior experience, self-correction, and novel behavior, and defines G0–G4 guidance levels. This is unusually valuable because it provides an existing provenance vocabulary for future autonomy experiments.

### F-H008-03 — Generative learning is explicitly defined but not self-proven
CORE-012 requires movement from inherited knowledge through hypothesis, test, validation, generated knowledge, and potentially an ARGO-native rule. It also explicitly states that novelty is not truth and that promotion is governed. This establishes a formal generative-learning target, not proof that every observed novelty is independently generated.

### F-H008-04 — Learning promotion is deliberately separated from execution success
ENG-015 requires evidence, outcome verification, pattern extraction, validation, confidence, and promotion authority. EJR-041 and EJR-049 document the same boundary. This materially reduces the risk of falsely counting successful execution as learning.

### F-H008-05 — Real connector training provides behavioral learning evidence
EJR-317–EJR-323 document a capability-first training sequence involving inventory, controlled probes, observed failures, schema corrections, reusable rules, negative controls, and revised interpretations. These are stronger behavioral indicators than static architecture, but their autonomy attribution is still unresolved because the training program itself supplies the learning methodology.

### F-H008-06 — The strongest evidence currently supports environmental/model learning, not independent meta-learning
The connector records show that tool semantics, filtering, evidence classes, discovery boundaries, and semantic keys were learned and converted into reusable rules. The repository records explicitly call these training artifacts. The evidence supports learning behavior under a governed training methodology; it does not isolate autonomous invention of the training methodology.

### F-H008-07 — Search-learning history independently corroborates the observability principle
EJR-195 records a real retrieval defect where ordinary file search failed to expose artifacts that were recoverable through commit history and direct inspection. This is concrete evidence that the diagnostic process itself generated reusable search knowledge. However, the record also explicitly frames the learning as session evidence rather than automatically promoted autonomous knowledge.

### F-H008-08 — Solution rejection is itself preserved as learning
EJR-311 retains rejected and future solution patterns rather than discarding them. This supports a learning architecture capable of preserving alternative reasoning and failure-derived knowledge. It is not proof that ARGO independently originated every preserved pattern.

## New experiment requirement

Future autonomy candidates should be tested against the existing G0–G4 vocabulary.

The minimum useful design is:

`Known Method → Controlled Failure → Remove Guidance → ARGO Diagnosis → New Strategy Not Supplied → Test → Improvement → Retention → Changed-Domain Transfer`

The critical transition is from a known/guided method to an independently selected method. Without that transition, a sophisticated learning result may still be guided learning.

## Handoff lesson for ARGO/HERMUZ

> **The fact that ARGO has a method for learning is evidence about its design. The fact that ARGO changes because of that method is behavioral evidence. The fact that ARGO independently changes the method itself is evidence of meta-learning. These three claims must remain separate.**
