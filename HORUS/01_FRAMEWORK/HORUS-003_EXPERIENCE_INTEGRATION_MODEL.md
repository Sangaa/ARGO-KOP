# HORUS-003 — Experience Integration Model

Status: FOUNDATION
Purpose: determine whether ARGO creates knowledge by combining prior and new experience

## Core model

`Prior Experience(s) + New Experience + Observation + Context Change → Common Pattern → Integrated Knowledge Candidate`

HORUS must distinguish three outcomes:

1. **Accumulation** — another experience was added without changing the existing model.
2. **Integration** — multiple experiences were connected under a reusable principle.
3. **Emergence** — the combination supports an insight, capability or explanation that was not explicitly present in the source experiences individually.

## Integration tests

A candidate integrated learning should be tested for:

- source traceability;
- novelty relative to each source experience;
- compatibility with prior knowledge;
- contradiction with existing knowledge;
- transfer to a materially different context;
- counterexample resistance;
- practical usefulness;
- evidence strength.

## Cross-domain rule

A similarity between domains is a hypothesis, not proof of a shared principle. HORUS must identify the mechanism that makes the transfer valid.

Examples of source domains may include Python, Git/GitHub, search/retrieval, connectors, testing, memory and prior ARGO engineering experience. Domain names do not establish equivalence.

## Novelty test

A result is not novel merely because it has a new label. HORUS should ask:

`Could the same conclusion have been generated directly from one existing experience?`

If yes, classify it as refinement or restatement unless additional evidence establishes a materially broader capability.

## Promotion boundary

Integrated or emergent knowledge remains analytical until validation and handoff criteria are satisfied. HORUS must preserve the source graph even after promotion.
