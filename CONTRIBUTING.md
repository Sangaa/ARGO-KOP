# Contributing to ARGO KOP

Thank you for your interest in contributing to ARGO KOP.

ARGO KOP is a Knowledge Operating Platform built around engineering discipline, governance, and long-term maintainability.

Every contribution should improve the platform while preserving its architectural integrity.

---

## Before You Contribute

Every contributor should first read the following documents in order:

1. START_HERE.md

2. README.md

3. VISION.md

4. CORE-005_PLATFORM_CHARTER.md

5. CORE-004_PLATFORM_CONSTITUTION.md

6. REP-001_MASTER_INDEX.md

Understanding these documents is required before proposing any modification.

---

## Core Principles

Every contribution shall respect the platform principles.

Reality Before Theory

Keep It Simple

Knowledge Before Code

Architecture Before Implementation

Repository is the Single Source of Truth

Traceability Before Speed

Consistency Before Convenience

---

## Contribution Philosophy

ARGO KOP values quality over quantity.

A small, well-designed improvement is always preferred over a large, inconsistent change.

Every modification should make the repository easier to understand, maintain, and evolve.

---

## Types of Contributions

The following contributions are encouraged:

• Documentation improvements

• Architecture enhancements

• Knowledge organization

• Repository maintenance

• Standards refinement

• Templates

• Examples

• Cognitive engineering concepts

• Platform improvements

---

## Before Creating New Documents

Before adding a new document, verify that:

The information does not already exist.

The document belongs to the correct component.

The document follows the naming standard.

The document includes the required metadata.

The document adds value to the platform.

---

## Architecture First

ARGO KOP follows an architecture-first approach.

Do not introduce changes that violate the established architecture in order to achieve short-term convenience.

If the architecture must evolve, update the architecture documentation before implementing the change.

---

## Repository Rules

Do not duplicate knowledge.

Do not remove historical information.

Do not rename documents without updating references.

Do not introduce inconsistent terminology.

Always preserve repository traceability.

---

## Documentation Standards

Every document should be:

Clear

Focused

Consistent

Traceable

Reusable

Technology Independent whenever possible.

---

## Decision Process

Significant changes should include:

Purpose

Reason

Expected Benefits

Possible Risks

Affected Components

Related Documents

This ensures every important decision remains understandable in the future.

---

## Commit Philosophy

Every commit should represent a meaningful improvement.

Avoid commits that combine unrelated changes.

Commit messages should clearly describe the purpose of the change.

---

## Pull Requests

Each Pull Request should include:

Summary

Motivation

Affected Components

Compatibility Impact

Documentation Updates

Related Decisions

---

## Review Criteria

Contributions are evaluated according to:

Architectural Consistency

Knowledge Quality

Documentation Quality

Repository Standards

Long-Term Maintainability

---

## What Should Be Avoided

Avoid unnecessary complexity.

Avoid duplicated concepts.

Avoid undocumented architectural changes.

Avoid technology-specific assumptions.

Avoid temporary solutions becoming permanent architecture.

---

## Final Principle

Every contribution should leave ARGO KOP in a better state than it was before.

---

Thank you for helping build ARGO KOP.

Decisions Preserved.

Intelligence Connected.
